# Skill & Map Engine Architecture — Wuxing Skills
> **System Architecture & Development Rules Guide for AI Developers**

This document defines the directory structure, the overall architecture of the VFX system, the smart-control mechanism, and the mandatory rules for developing skills, maps, or environment features.

---

## 2. Core Architecture Pillars

### A. Drag-to-Cast Input Mechanism (Free-Path Drawing)
- **How it works:** Instead of an instant click on a single target location, the system supports Vector Targeting. The player holds down the left mouse button (or a touch), dragging out a winding path across the ground. On release, the skill fires.
- **Parameter passing:** `SkillParams` contains:
  - `int pathPointCount`: number of drawn points (max 32).
  - `Vector3 pathPoints[32]`: array of 3D coordinates along the path.
- **Motion interpolation:** Skills like `seismic_pillars` (stone pillars) or `wood_thorns` (wood thorns) use linear interpolation or distance interpolation between drawn points (`Vector3Lerp`) to place objects growing sequentially along the exact hand-drawn winding path, instead of firing in a straight line.

### B. Dynamic Map System (Map Manager System)
- **Dynamic loading:** managed via `MapManager`. Maps live independently in the `maps/` directory. Key `K` swaps maps instantly during gameplay.
- **API contract:** every map plugin must expose these lifecycle functions:
  - `Init[Name]Map(void)`
  - `Update[Name]Map(float dt)`
  - `Draw[Name]Map(void)`
  - `Unload[Name]Map(void)`
- **Auto-registration:** the `scripts/generate_map_registry.py` script automatically scans subdirectories in `maps/` to generate a registry wired into `core/map_manager.c`.

### C. Smart Lighting & Shadows (Environment System)
- **Fake Shadows:** uses `environment_system.c` to project 2D fading oval shadows flush to the ground beneath characters and enemies, working around the performance cost of real-time shadow mapping in Raylib.
- **Static Occluders:** register static light-blocking pillars (`RegisterStaticOccluder`) to cast long static shadow streaks across the arena floor aligned with the main light source's direction.

### D. Core VFX System (VFX Helper APIs)
- Provides bundled functions (VFX Presets) in `skill_helper.c` for quick invocation while protecting performance:
  - `SpawnImpactEffect`: quickly fires a preset explosion (fire, water, smoke, shake, lens distortion).
  - `SpawnDamageVolume`: creates a self-destructing circular/box damage-over-time (DoT) volume.
  - `DrawEffectMesh`: draws basic meshes with flat shading and clear-edged face normals — tetrahedron (`TETRAHEDRON`), pyramid (`PYRAMID`), flat-capped cylinder (`CYLINDER`), cone (`CONE`), sphere (`SPHERE`).

## 3. Mandatory Development Rules for AI

### 1. Required file-naming rules (must not change):
For the Python auto-scan scripts that generate registry configuration to work correctly, file naming must strictly follow:
- **New skill:** stored at `skills/<element>/<name>_skill/<name>_skill.c` and `skills/<element>/<name>_skill/<name>_skill.h`.
- **New map:** stored at `maps/<map_name>/<map_name>.c` and `maps/<map_name>/<map_name>.h`.

### 2. Depth Mask & Depth Test rules:
- Always call `rlEnableDepthMask()` and `rlEnableDepthTest()` at the start of the draw function for closed 3D meshes (stone pillars, spikes) to prevent see-through-each-other and see-through-ground/decal artifacts.
- Conversely, for alpha-blended particles drawn afterward, call `rlDisableDepthMask()` when using `BLEND_ADDITIVE` mode to avoid unnaturally occluding particles behind them.

### 3. Rules for loading Alpha textures onto 3D Meshes:
- Never multiply a texture's Alpha channel (e.g. a cracked-earth texture) directly into the diffuse color in a closed 3D mesh's fragment shader — this creates strange see-through holes into the mesh's hollow interior.
- Always keep a mesh's Alpha at `1.0f` in the shader; only multiply the texture's RGB to create dark-colored cracks.

### 4. Token Efficiency (Protect the Context Window):
- Never grep-scan the entire project. Never read the excluded directories: `_deps/`, `build/`, `android.wuxing_skills/`.
- When needing to understand a core API, **only read the `.h` header file** (e.g. `core/particle_system.h`). Never open and read the core system's `.c` implementation file.
